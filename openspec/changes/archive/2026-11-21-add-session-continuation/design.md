# Design

## Context

See proposal.md for motivation. Existing `history.Service.List`, `Read`, and `Describe` own discovery, pagination, format/confinement checks, and reference validation. Catalog offsets count candidates/skips, not returned sessions; limits are 50 default/500 maximum and pages are not a snapshot. Read returns native file order rather than reconstructed active context. `handoff.ParseBrief` validates version-1 input, and `handoff.Service.Create` revalidates sources and atomically publishes immutable metadata-only handoffs. Existing create/list/show launch nothing. Strict config parsing currently returns early when sources are omitted; extension must preserve new settings on that path.

Local Pi CLI documentation confirms one-shot print mode, explicit provider/model selection, no-session, no-tools, no-MCP, no-extensions, no-context-files, and explicit file-based native session resume. Print mode exits nonzero for failed/aborted/token-limited responses; JSON mode instead requires inspection of event completion, so use print mode. Local Claude/Codex help confirms fresh interactive sessions accept an initial prompt, but a transcript's readability is not proof of its native resumability. No real histories or model invocations were used for planning.

## Goals / Non-Goals

**Goals:** A useful find-to-continue workflow, with shared application orchestration and small injectable process adapters. Keep discovery, model disclosure, publication approval, and receiver launch as separate trust transitions. Maintain standalone Go distribution on Darwin/Linux.

**Non-Goals:** Source transcript mutation during browsing/drafting, arbitrary shell templates, automatic permission approval, cross-machine continuation, session format conversion, persistent drafting agents, or native resume claims for unproven mappings. After an explicitly approved native resume, the original harness may append to its session under its normal behavior; Spool's own history reads remain read-only.

## Decisions

### Command and state transitions

`spool pick [--config FILE] [--harness pi|claude|codex] [--ref]` requires terminal stdin/stdout. Normal Enter opens actions: inspect, resume original (if supported), prepare handoff, or cancel. Inspect shows one bounded read as escaped JSON on stderr and returns to the action menu; it never calls the drafter. `--ref` revalidates and emits the exact chosen reference plus LF without actions. Help succeeds without dependencies. Spool's own UI/status uses stderr and emits no stdout in normal mode. After explicit launch/resume authorization, the interactive child inherits stdin/stdout/stderr and may write to them normally; the empty-stdout promise does not apply to child terminal output. Completed/save-only actions exit 0, failures/empty/no-match 1, invalid arguments/config/non-TTY 2, missing session 3, cancellation 130. Child failures map to operational failure rather than inheriting undocumented harness exit meanings.

Handoff states are selected source -> target and user-entered continuation goal -> prepared source scope -> disclosure confirmation -> drafting -> validation -> review/edit -> approval -> immutable publication -> save-only or separate launch confirmation. Edits or regeneration invalidate approval. Declining launch after publication is successful save-only, not a rollback of the approved handoff. Failures before publication publish nothing; failures after publication preserve the handoff and identify it for manual recovery. Cancellation never retries a model or switches targets.

Use a shared `internal/continuation` orchestration service with injected history/handoff interfaces and drafter/launcher interfaces. CLI owns fzf, review prompts, and editor interaction. Service methods prepare input, draft, validate, publish, and construct typed launch plans; no launch happens as part of list/read/create. Approval binds the exact validated bytes plus source ref, scope digest, target, and goal in the current process; it is not inferred from the existence of a draft file. No new MCP/remote interface is added on this baseline.

### Catalog, fzf, and terminal boundaries

Reuse List at MaxLimit, continuing only by NextOffset until nil, including empty pages. Reject nonadvancing offsets, deduplicate refs in first-seen catalog order, and deduplicate repeated diagnostics on stderr. A successful page containing partial-source diagnostics remains usable. Any failed pagination request, including after successful pages, aborts the entire picker before fzf starts, reports failure, and exits 1; accumulated rows are not offered. Collect all rows before launching fzf; memory grows with catalog size, there is no silent cutoff, and changing histories can still cause omissions. Document these costs rather than promising snapshot behavior or newest-first ordering.

Rows are tab-delimited ref, harness, recorded started_at, cwd, title. Unknown visible values are blank. Strip control characters, line/paragraph separators, and bidi controls from labels/diagnostics without altering underlying records or refs. Disable ANSI interpretation; configure tab delimiter, visible/search fields 2 onward, and single selection. Clear FZF_DEFAULT_OPTS, FZF_DEFAULT_OPTS_FILE, and FZF_DEFAULT_COMMAND. Launch the resolved fzf directly using inherited PATH, not a shell. Capture and bound stdout to one supplied row; require exact offered-row/ref membership and canonical ref validation. Never reconstruct identity from labels.

Preview is a fixed, POSIX-quoted invocation of this executable's `read`, with the same absolute explicit config path if supplied and `--` before fzf's `{1}` placeholder. Fix SHELL to /bin/sh, quote all static paths, and never interpolate other fields. Preview returns only a first default-sized page/error JSON and does not decode controls or paginate. Test actual shell execution with hostile static paths. Probe terminal descriptors via small Darwin/Linux ioctl helpers rather than character-device mode alone; fake terminal approval is injectable only in tests. No terminal framework dependency is required.

### Optional config and provider selection

Extend strict version-1 config with optional `drafting: {"provider":"example-provider","model":"example-model","thinking":"medium","timeout_seconds":120,"max_input_bytes":131072}`. Provider and model are required when this block is present; thinking is optional from Pi's documented enum. Timeout is positive and at most 600 seconds; max_input_bytes is positive and at most 1 MiB. Defaults within a configured block are 120 seconds and 128 KiB. Absent block means unconfigured drafting, not an automatic model choice. Keep configured model IDs exact and provider explicit; never fall back to another model. Config location remains existing XDG behavior, including --config overrides. Parse this block whether sources are explicit or defaulted; reject unknown fields/duplicates/null or invalid types consistently.

Credentials/custom endpoints remain in Pi's normal provider setup and inherited environment, never copied into Spool config or command arguments. Pi and the configured provider settings are trusted optional integrations, not an OS sandbox; no-tools prevents model-directed actions but cannot make a malicious Pi executable/provider module safe. Discover Pi on inherited PATH only when drafting is requested. Failure to configure drafting must not break browsing/list/read/handoff storage. Configuring it is not consent to send history.

### Source scope, privacy, and drafting process

Initially draft from exactly the selected session; additional sessions are out of scope. Read through the shared service from physical-line offset 0, consuming returned pages until EOF or the configured encoded-input budget. Stop at a nonadvancing/incomplete-tail offset, never retry in a loop, and never split native records. Count the entire serialized prompt data, including metadata/diagnostics; fail if even the required framing cannot fit. Show included line ranges, omitted/oversized/malformed data, non-EOF state, target/goal, provider/model, and byte budget before confirmation. Budget counts bytes, not model tokens; provider context overflow is a visible failure, not a silent truncation/retry. History may contain secrets and will leave the machine for a configured remote provider; warn explicitly. Do not claim redaction or freshness.

Invoke Pi directly with typed argv: --print, --no-session, --no-tools, --no-mcp, --no-extensions, --no-skills, --no-prompt-templates, --no-themes, --no-context-files, --no-approve, --offline, explicit --provider/--model and optional --thinking, plus a fixed system prompt requiring only the brief-content JSON schema. The offline flag suppresses Pi's automatic background catalog activity, not the explicitly authorized model request. Use a fresh private temporary cwd outside history/workspaces; no continue/resume/session-file flags. Send the prompt/history via stdin, never argv. The prompt is fixed framing plus user goal and JSON-encoded untrusted data, not a user-controlled Pi command or slash command. Disable discovered resources even when the normal user configuration enables them. Do not copy credentials or edit Pi settings; custom provider authentication remains delegated to the installed Pi integration.

Capture bounded stdout (256 KiB maximum, matching existing brief input limit) and bounded sanitized stderr (32 KiB); enforce timeout/cancellation and reap children. Treat any nonzero exit, overflow, invalid UTF-8/JSON, duplicate keys, missing fields, or token-limited output as failure. Do not parse fences or repair JSON with another hidden model call. The model returns only title/goal/content-list fields; reject sessions/workspace/repository/target/executable fields. Spool attaches the selected ref, confirmed workspace, and trusted scope/model caveats itself, then validates the assembled version-1 brief. Generated assertions remain unverified even if structurally valid.

### Review, storage, and provenance

Show a safe rendered draft, scope summary, provider/model, and target before offering edit, approve, or cancel. Editing uses a 0600 draft file in a 0700 temporary directory, a deliberately chosen trusted editor from VISUAL/EDITOR, parsed as argv without shell expansion, and no shell command templates. If no editor is configured, offer approve/cancel or explain how to configure one; never select an arbitrary program from transcript text. After editor exit, reject symlink/nonregular/replaced-outside-container input and read with strict bounds. Validate the brief, ensure sessions/workspace/scope metadata remain application-owned, and require a fresh explicit approval of the edited bytes. Editor use is a deliberate local action and is not run during browsing or model generation.

Published storage stays version 1: no undocumented fields or version bump. Add explicit notes that content was model-drafted/user-approved, identify provider/model and physical-line coverage/omissions, and warn that recorded paths/claims are unverified. These notes are visible claims, not machine-authenticated generation provenance. Existing Create/ParseBrief/Render perform validation, source snapshotting, safe rendering, and immutable publication. Use a confirmed workspace rather than the isolated drafter cwd or untrusted recorded cwd. Revalidate source before publication; missing/unsupported references fail through existing codes. All temporary draft/input files are private and removed on ordinary completion/cancellation; crash leftovers are a documented privacy limitation and are not published handoffs.

The existing session-handoff no-generation statement is scoped to create; create/list/show remain action-free with unchanged machine-readable responses and literal supplied content. Update documentation's blanket no-model/no-launch statements to name this explicitly authorized continuation exception without weakening read-only history guarantees.

### Native resume and receiving clients

Initial native resume supports local Pi regular session files revalidated by Describe and mapped to their exact original file path. Display the path and recorded cwd as unverified metadata, ask the user to confirm an existing local workspace, and invoke `pi --session ABSOLUTE_SESSION_PATH` with no prompt. Pi may apply its own recorded working-directory behavior, so require the chosen directory to match the session's existing recorded cwd for this adapter; a missing/different cwd uses handoff rather than silently forking/relocating. Bind confirmation to the exact reference, source/file identity, supported format/kind, and recorded cwd. Immediately before spawn, re-run Describe and regular-file/confinement checks and compare that identity and cwd to the confirmed candidate. A detected replacement or relevant change invalidates confirmation and requires renewed review; disappearance fails without launching. Do not use ambiguous partial IDs or most-recent resume. Validate supported Pi format/version/session kind; unsupported mappings show why resume is unavailable. A residual pathname race remains between final validation and Pi opening its session file; do not claim Describe eliminates it or silently copy/fork the source as a workaround. Claude/Codex native resume remains disabled until source-root, duplicate-ID, subagent, archive, and harness-native lookup behavior is proven; CLI help alone is not proof.

Fresh-session handoff targets are Pi, Claude Code, and Codex. On explicit launch confirmation, create an owner-only rendered approved brief file outside all configured history roots and hand the target a short fixed initial prompt identifying that file as approved but historically unverified, asking it to read the file and verify workspace state. Pass only the file location in argv, not transcript/brief/credential contents; labels never become options. Use interactive `pi -- FIXED_PROMPT`, `claude -- FIXED_PROMPT`, or `codex -- FIXED_PROMPT` through direct exec with confirmed cwd and inherited terminal streams, no continue/resume flags, no permission-bypass flags, and no arbitrary configurable argument templates. Await the child to preserve terminal ownership and keep the private brief file alive, then clean it up. The target's normal auth, project trust, and permission behavior apply; explicit launch authorizes its normal startup, not auto-approval by Spool. If a target cannot safely ingest the file with its normal user permissions, report failure and leave the saved handoff for manual use rather than granting access automatically.

The user may save without installing any target harness. A launch confirmation identifies executable, target, cwd, and approved handoff ID; changing any invalidates confirmation. Failed launch does not undo immutable publication. The local model configured for drafting is independent of whichever model the receiving interactive client uses.

## Risks / Trade-offs

- [Model transmission exposes secrets and costs money] -> Confirm the exact source/scope/provider, use bounded input, and make no redaction promise; browsing stays offline.
- [Prompt injection or bogus model assertions] -> Tool-free resource-disabled drafter, application-owned references/launch plans, strict output validation, and human review; review cannot guarantee truth.
- [Full-catalog scans and non-snapshot source reads are costly/incomplete] -> No hidden cap, explicit budgets/coverage, deduplication, and cancellation. A future measured optimization can add snapshots or streaming separately.
- [Pi/harness CLI drift and optional integration failures] -> Document supported flag contract, fail closed on unsupported options, fake-process contract tests, and retain save-only/manual recovery.
- [Native resume can alter a source via the harness] -> Separate explicit confirmation and conservative capability gating; never describe it as a read-only operation.
- [Source histories differ from current workspace] -> Confirm local cwd, preserve provenance, and instruct the receiver to verify current state; no code/branch transfer.
- [Draft files and inherited provider configuration are sensitive] -> Owner-only temporary storage, no content logging/argv, bounded capture, and documented crash/provider trust limitations.

## Migration Plan

Add optional config fields without changing existing absent-config/default-source behavior or stored handoff version. Existing list/read/create/list/show retain output, exit, and dependency contracts. Ship the picker/drafter/launch services only after focused fake-process tests and security boundary checks pass. Rollback removes new command/config support; existing immutable version-1 handoffs remain readable. Only this change's artifacts belong in the proposal PR; the older unpublished picker exploration is superseded and must not be implemented alongside it.
