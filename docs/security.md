# Local continuation security boundaries

History is untrusted historical data, never instructions or evidence of current workspace state. List/Read/Describe and authored handoff create/list/show invoke no model or harness. Picker browsing/preview/inspection stays read-only and never transmits to a provider. This scoped inert-operation promise does not describe separately confirmed continuation integrations.

Continuation has separate trust transitions: explicit source/goal/target/provider/model/scope disclosure before a tool-free nonpersistent drafter; strict validation and exact-byte user approval before immutable publication; separate executable/cwd/handoff confirmation before interactive launch, or separate exact-file/workspace confirmation before native Pi resume. Configuration is not consent. Historical labels, model fields, and editor content cannot select commands, invent source identities, or silently change application-owned workspace/scope metadata. Controls and bidi formatting are stripped or visibly escaped at terminal boundaries. Processes use direct argv and inherited PATH, never transcript interpolation into shell commands. Only fzf's static same-executable read preview uses fixed POSIX shell quoting of static paths and the canonical ref placeholder.

Pi/provider/editor/target executables are trusted optional integrations, not an OS sandbox. Credentials/custom provider commands remain owned by Pi. Model transmission can expose secrets/private code and incur costs; Spool provides no redaction guarantee. No tools, resources, MCP, project context, session persistence, default appended prompts, or automatic catalog/package activity are available to the isolated drafter. Historical input goes on stdin, not argv/logs. Model-generated claims are unverified even after user approval. A receiving or resumed interactive harness retains its normal startup, authentication, trust, and permission behavior; launch never grants blanket tool approval. Native Pi resume may append to original history and retains a documented residual pathname race.

Private temporary draft/brief directories are owner-only, checked outside all configured history roots (enabled or not, including aliases), and removed on ordinary completion/cancel. Drafting additionally excludes recorded and confirmed workspaces. Crashes can leave sensitive private files. Published handoffs are immutable version-1 local metadata-only records, not encrypted transcript replicas or authenticated provenance. Failures before publication leave no handoff; failures after publication preserve it for manual recovery. Filesystem checks assume trusted ancestors not concurrently renamed by a same-user process. See [continuation.md](continuation.md), [architecture.md](architecture.md), and [handoffs.md](handoffs.md) for exact contracts and limitations.
