# Local literal search

`spool search [--config FILE] [--harness pi|claude|codex] [--case-sensitive] [--limit N] [--cursor CURSOR] QUERY` searches local native histories on demand. Use `spool search --config FILE -- -needle` when the literal query starts with `-`, or `spool search --config FILE -- --` to search for two dashes. No harness executable, network service, persistent index, cache, embedding, or write to source files is involved; MCP and remote search endpoints are not implemented.

A query is valid UTF-8, contains at least one non-whitespace code point, and is at most 256 bytes. Internal spaces remain literal. Default comparison uses one-code-point Unicode simple folding (`K` matches `K`, `s` matches `ſ`, `Σ` matches `ς`), not normalization (`é` does not match `e` followed by a combining accent) or expansions (`ss` does not match `ß`). `--case-sensitive` compares original code points. Metacharacters such as `.*` are literal. Matches cannot cross text fields or physical records; the first occurrence in the first matching field produces one hit per record.

## Searchable native text

Only the following JSON-string leaves are searched, decoded once from their native JSON. Pointers in hits identify the exact leaf with RFC 6901 array indexes. Unknown or wrong-shaped fields contribute no text; this is not a complete conversation search. Use `spool read` to inspect full records.

| Harness | Allowlisted record text | Field pointers |
| --- | --- | --- |
| Pi | `message.message.content` as a string or ordered `type: "text"` blocks (including toolResult); `branch_summary.summary` and `compaction.summary` strings | `/message/content`, `/message/content/N/text`, `/summary` |
| Claude Code | `user`/`assistant` `message.content` as a string or ordered text blocks; `tool_result.content` as a string or ordered nested text blocks; top-level `summary.summary` string | `/message/content`, `/message/content/N/text`, `/message/content/N/content`, `/message/content/N/content/M/text`, `/summary` |
| Codex | `response_item` with `payload.type: "message"`: ordered `input_text`, `output_text`, or `text` blocks; `function_call_output.payload.output` string; `compacted.payload.message` string | `/payload/content/N/text`, `/payload/output`, `/payload/message` |

A Codex output string containing JSON is searched as the recorded string, never recursively reparsed. Excluded text includes Pi thinking and tool-call arguments; Claude tool-use input, `toolUseResult.stdout/stderr` mirrors, images, and attachments; Codex `event_msg` mirrors and function-call arguments; and every harness's titles, IDs, paths, usage data, arbitrary extension fields, binary/base64 payloads, and unknown block or record types. Search cannot infer active conversation branches, follow inherited-history references, or treat historical tool output as current workspace evidence.

## JSON response and citations

Success writes one JSON object followed by a newline with `version: 1`, `ok: true`, `content: "untrusted_history"`, `view: "native_file_order"`, `sources`, `hits`, `limit`, `next_cursor` (string or null), `eof`, `partial`, `diagnostics`, and `omitted_diagnostics`. An individual hit has `session` (the existing Session metadata with opaque `ref`, source ID, harness, original path, and native identity), `line` (1-based physical record line), nullable native `type`, `subtype`, `id`, `parent_id`, `timestamp`, `field` (JSON pointer), `snippet`, `match_start`, `match_end`, `truncated_before`, and `truncated_after`. Positions are zero-based half-open Unicode code-point indexes into the snippet, not byte indexes. A snippet contains the complete match with up to 96 preceding code points and at most 512 code points total; near the end it backfills earlier context. It never inserts ellipses; truncation is reported separately. The original full native line remains available through `spool read --offset N --limit 1 SESSION_REF`, with N equal to hit line minus one.

Search snippets and metadata are **unredacted sensitive historical data** and may include secrets or instructions. `untrusted_history` labels them as historical data, never instructions for Spool or a caller to execute. Spool neither executes history content nor launches agents. Output order is source ID, slash-relative path, and physical line, not relevance or active branch order.

## Continuation, bounds, and failures

The default hit limit is 50, maximum 500. Pass the returned `next_cursor` as `--cursor` with the same query, harness filter, case mode, and selected source configuration; the hit limit may change. For example: `spool search --config FILE --limit 1 widget`, then `spool search --config FILE --limit 20 --cursor 'q1.…' widget` using the exact cursor value returned by the first command. A cursor is an opaque canonical `q1.` locator, not a path or credential; malformed, mismatched, oversized, and out-of-range cursors fail with `invalid_request`. When `eof` is true, no continuation remains in the captured traversal; EOF does not claim damaged or excluded files were searched. A page can be empty with `eof: false` and an advancing cursor when work limits stop before a match.

Each request processes at most 256 discovered candidate or filesystem-issue rows and reads at most 128 MiB of native file bytes, counting underlying reads and JSONL read-ahead and discarded oversized lines. Each file is capped at its captured 64 MiB extent; a physical line over 4 MiB excludes the entire file with `oversized_line`, even if an early match was provisionally found. A file over 64 MiB is excluded with `session_too_large`; when the next captured file exceeds the remaining request allowance or row allowance, `scan_limit` returns a continuation before it. These are native-content scan bounds, **not** a hard whole-command latency or memory bound: existing discovery still walks directory entries to sort the catalog. A response is capped at 8 MiB serialized with at most 64 retained diagnostics and an omitted count. A hit too large to fit an otherwise empty response's allowance is skipped with a source/line `record_too_large` diagnostic and continuation advances.

Before committing a file's hits, search parses its identity and standalone format through the captured extent on the same confined open file; late Claude fork-context references, Codex composite-history markers, missing or conflicting identities, oversized physical lines, and changed files exclude the whole file. Non-header malformed complete lines yield `malformed_line` and other eligible lines may still match. An unterminated tail yields `incomplete_tail`, withholds that final record, and does not trap cursor progress. For example, if line 2 matches, line 3 is malformed, and line 4 matches with `--limit 1`, the first page returns line 2, reports malformed line 3 once, and stops before line 4; the next page revalidates the file and returns line 4 without repeating the line-3 diagnostic. If late session metadata makes an earlier provisional hit exceed the response allowance, only diagnostics before the final continuation line are delivered; diagnostics after that line remain for resumed pages. Restart a search (omit `--cursor`) after appends, truncation, tail completion, renamed files, changed source roots, or other history mutations: cursors are **not snapshots**, and later appends fall outside the previous captured extent. An observable same-size modification or replacement during validation excludes the file; an undetectable same-length concurrent rewrite cannot be ruled out atomically.

Absent built-in roots are normal empty sources. Explicit roots that fail appear as source errors with diagnostics; other usable roots remain searchable with `partial: true`. Only when every selected root fails does the request fail with `sources_unavailable`. Malformed and unsupported individual candidates never become root failures. Exit status is 0 for success including partial results, 1 for operational failure or cancellation, and 2 for invalid request or configuration. Neither search nor its continuation changes existing `list`/`read` pagination or source behavior.
